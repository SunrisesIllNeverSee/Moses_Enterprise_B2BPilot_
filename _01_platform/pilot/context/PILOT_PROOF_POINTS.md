# PILOT_PROOF_POINTS.md

> Catalog of the strongest demonstrated capabilities of the current
> Upsilon platform.
>
> This document prevents already-built capabilities from being
> forgotten or unnecessarily rebuilt. Every proof point is grounded
> in repository evidence and runtime validation.
>
> This document is NON-CANONICAL. It catalogs demonstrated
> capabilities but does NOT define specifications.

## Evidence classification

Each proof point is classified as one of:

| Classification | Meaning |
|---|---|
| **ACTUAL COMPUTED EVIDENCE** | Value was computed from real/synthetic data by the running platform. Verified by instantiating `PilotService`. |
| **SYNTHETIC INPUT** | Input data is synthetic (generated by `scripts/generate_demo_data.py` with seed 50030). |
| **DEMONSTRATED RUNTIME CAPABILITY** | The capability runs and produces output. Demonstrated via CLI/TUI/MCP or service method. |
| **PLANNED CAPABILITY** | Specified in the pilot package but not yet implemented as runtime. |
| **CONCEPTUAL CLAIM** | Stated in documentation but not demonstrated by runtime. |

## How to use this document

1. **Before building a new capability**, check this document. The
   capability may already exist.
2. **Before claiming a capability is missing**, check the evidence
   column. The capability may be implemented but not recognized.
3. **When updating capabilities**, add or update proof points with
   runtime evidence.
4. **Do not delete proof points.** Even if a capability is
   superseded, the proof point documents what was demonstrated.
